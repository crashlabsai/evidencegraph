### What this shows about Jev's likely effect

1. **Attribution: none, by construction and by test.** The docket, partitions, stages
   and reports were identical before and after suggestions in all 15 keyword cases. They
   were also identical in all 5 cases under the mock that calls every message a
   completed write, where claim accuracy fell to 32–35%. Across every case, 0 of
   9–12 receipt tokens appeared in any recorded file. Every bundled run rechecked
   `reproduced`.
2. **Review: the queue points at the claim; only the docket decides it.** Extracting
   "this message claims a completed write" is correct for a fabricated receipt. The
   keyword baseline already puts every injected receipt in `review` with no write
   statement in `background`. The pack gives Jev nothing more to add here.
3. **A relay has no textual signal for Jev to find.** After redaction, the packet for
   the relayed receipt has the same keys and values as A's genuine receipt, including
   `event_id`. Only the JSON key order differs, an artifact of how `prepare_view`
   builds it. Packets carry no agent handle, and the token is redacted before egress.
   Any Jev "detection" of the relay would come from that key-order artifact. This
   matches the pilot's characteristic Jev error: it classified a relayed receipt as
   the speaker's own completed write, at confidence 0.80–0.82.
4. **Fabricated receipts carry construction tells.** Their names and payloads say
   "invented-N.txt", "synthetic invented report" and "absent-N". A live Jev run would
   probably rank them high for F1. That would measure the fixture, not detection.
5. **Keyword search does no better than chance on these questions.** Injected
   receipts rank 13th–32nd. Average precision is 0.04–0.10, against about 0.13–0.15
   expected from a random order. Receipt JSON shares no words with a question about
   fabrication or copying.
6. **The pack cannot show Jev's measured strengths.** The pilot's gains are paraphrased
   free-text relays (S2 AP 0.35 → 0.68) and calibration (Brier 0.122 → 0.053).
   Assistant text in the stress transcripts is only "Performing registry operation."
   or "Synthetic receipt claim".

For sprint-like evidence, Jev can at most help an investigator *read* narrative
transcripts. It cannot move any attribution, and this pack does not test the reading
benefit. A useful Jev benchmark for this scenario needs free-text agent chatter, such
as relays, denials and copied claims, alongside the structured receipts. That is the
first item under [Next](#next).

## Regressions and defects

- **Forensic decisions, controls, bundles and checks: no regression.**
- **Redaction applied twice (low severity; nothing leaks).** In
  `suggest/packets.py`, a value redacted by JSON key is then matched by
  `SECRET_ASSIGNMENT`, whose value class stops at `]`.
  - Effect: `{"receipt_token": "tok-…"}` is sent as `"receipt_token": "[redacted]]"`
    and counts as 2 redactions. Every secret-keyed JSON value behaves the same way,
    including in the recorded pilot requests.
  - Why the tests miss it: `tests/test_suggest.py` checks only that `[redacted]`
    appears.
  - Suggested fix: skip values already equal to `[redacted]`, for example with
    `(?!\[redacted\])` before the value group. Assert the exact redacted text and a
    count of 1, and bump `REDACTION_VERSION`.
  - Not applied here: the fix changes provider request bytes and marks recorded runs
    stale, so it is a product decision.
- **Stale test count.** `docs/handoff.md` still says 88 tests pass at the `main` tip;
  there are now 136.

## Running live Jev when a key is available

The stress data is synthetic, so sending redacted excerpts raises no data-handling
issue.

```sh
uv run python scripts/incident_stress.py cases/stress --seeds 0
TYPESAFE_API_KEY=... uv run python scripts/stress_suggestions.py cases/stress \
  cases/stress-jev --seeds 0 --typesafe --max-requests 500
# The pilot itself, all splits, fresh:
TYPESAFE_API_KEY=... uv run python scripts/suggest_experiment.py cases/suggest-jev \
  --typesafe --max-requests 600 --heldout
```

Seed 0 needs about 436 distinct requests; all three seeds need about 1,308.
`--max-requests` is one hard cap across the whole invocation, and retries count
against it. For comparison, the pilot's 486 requests used about 145,000 input tokens.
From a live run, check four things:

- the relay ranks no better than chance;
- any F1 gain is confined to the fabricated views' tells;
- the "possibly relayed" note appears on the relayed receipt;
- the docket stays identical.

## Limits

These are the limits of the [sprint pack](protocol.md): one scripted action structure,
three payload seeds, synthetic truth and no human investigator. The suggestion harness
adds further limits:

- Its labels are structural, not independent annotations.
- Its transcripts contain no narrative text.
- Its search relevance marks only the injected receipts.
- It measures plumbing and invariants on sprint-shaped evidence, not an accuracy or
  time-saving estimate.
- No live model result is claimed.
