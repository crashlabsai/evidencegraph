### What the live run shows

1. **Attribution is unaffected.** The forensic state was identical before and after
   suggestions in three settings:
   - with live Jev;
   - on all 15 keyword cases;
   - under the mock that calls every message a completed write, where claim accuracy
     fell to 32–35%.
2. **For review, Jev agrees with the keyword rules.** Both extract every injected
   receipt as a claim of a completed write, which is what the receipt says. Neither
   adds a relay note to the relayed receipt, because nothing in its text says relay.
   The queue points at the claim; only the docket decides it.
3. **Jev cannot see the relay, and ranks it least suspicious.** After redaction, the
   relayed receipt has the same keys and values as A's genuine receipt, including
   `event_id`. Only the JSON key order differs, an artifact of how `prepare_view`
   builds it. Packets carry no agent handle, and the token is redacted before egress.
   - Among the ten write receipts in the relay case, Jev scored the relayed one
     lowest: F1 1.94 against 2.09–2.23, and S2 0.58 against 0.63–0.75.
   - The copied public receipt, which has no token, also scored lowest: F1 1.98
     against 2.05–2.23, and S2 0.08 against 0.67–0.71.
4. **Jev's F1 gains come from fixture wording.**
   - On the fabricated views, Jev ranked the invented receipts third and fourth (F1
     2.47 and 2.42, against at most 2.25 for genuine receipts). Their names say
     `invented-N.txt`, and their payloads say "synthetic invented report".
   - Above them, for both questions in every injected case, Jev ranked the fixture's
     own "Synthetic receipt claim" calls first. Those calls are not labelled
     relevant. They are construction artifacts; a real fabricator would not announce
     itself.
5. **Jev's gains are in reading narrative, which this pack lacks.** Its measured gains
   are:
   - paraphrased free-text relays: pilot S2 AP 0.35 → 0.63–0.68;
   - calibration: Brier 0.122 → 0.051–0.053.

   Assistant text in the stress transcripts is only "Performing registry operation."
   or "Synthetic receipt claim".

For sprint-like evidence, Jev can help an investigator *read* narrative transcripts,
but it cannot move any attribution. On structured receipts it adds nothing beyond what
the keyword rules and the docket already give, and its search signal follows fixture
wording. A useful benchmark for this scenario needs two changes, the first two items
under [Next](#next):

- free-text agent chatter (relays, denials, copied claims) beside the structured
  receipts;
- the fixture's giveaway wording removed.

## Regressions and defects

- **Forensic decisions, controls, bundles and checks: no regression.**
- **Redaction applied twice: fixed (redaction version 2).** In `suggest/packets.py`,
  a value redacted by JSON key was matched again by `SECRET_ASSIGNMENT`, whose value
  class admits `[`.
  - Effect: `{"receipt_token": "tok-…"}` was sent as `"receipt_token": "[redacted]]"`
    and counted as two redactions. A value already redacted under a secret key was
    counted again too. Nothing leaked, but the request bytes carried the artifact,
    including the recorded pilot's.
  - Why the tests missed it: the existing test only checked that `[redacted]`
    appeared.
  - Fix: a `(?!\[redacted\])` lookahead before the value group, and the key pass now
    skips values already equal to `[redacted]`. A new test asserts the exact output,
    a count of 1 and idempotence. It fails on the old code.
  - Consequence: request bytes change only for spans that contain a redacted key.
    Replaying a version-1 pilot run now answers 71 of 81 spans. The other 11 return
    `not_sent` and are listed as `unscored`. Because the suggestion code changed,
    earlier runs are already marked stale.
- **Stale test count.** `docs/handoff.md` still says 88 tests pass at the `main` tip;
  there are now 137.

For `stress_suggestions.py`, `--max-requests` is one hard cap across the whole
invocation, retries included. Seeds 1 and 2 would add about 870 requests, and they
vary only payloads. Jev is not bitwise deterministic, so a new run is a new
observation. The recorded exchanges stay in the gitignored `cases/` directories and
replay offline.

## Limits

These are the limits of the [sprint pack](protocol.md): one scripted action structure,
three payload seeds, synthetic truth and no human investigator. The suggestion harness
adds further limits:

- Its labels are structural, not independent annotations.
- Its transcripts contain no narrative text.
- Its search relevance marks only the injected receipts.
- It measures plumbing and invariants on sprint-shaped evidence, not an accuracy or
  time-saving estimate.
- Live Jev ran once on seed 0 and once on the pilot corpus. Each run is one
  observation of a model that is not bitwise deterministic, not a distribution.

## Next

1. Add free-text relay, denial and copied-claim messages to the stress worlds. Keep
   ground truth private, and score Jev against the keyword baseline on those messages.
2. Remove the fixture's tells from the injected events: "Synthetic receipt claim",
   `invented-N.txt`, "synthetic invented report" and `absent-N`. Keep the forensic
   contracts unchanged, so that text-based results cannot key on construction
   wording.
3. Include the conversation's agent handle, or neighbouring messages, in packets
   only if a controlled test shows it helps reading. It must still never touch
   attribution.
